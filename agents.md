# Capital — правила для AI-агентов

Финансовый трекер (PWA + Capacitor Android). Стек: Vanilla JS, Tailwind, Firebase.

## Запуск и проверка

- `npm run dev` — локальный сервер
- `npm run lint -- --fix` — **запускай после изменений и исправляй ошибки до завершения задачи**
- `npx cap sync android` — синхронизация перед сборкой APK

## Архитектурные ограничения

- **Оффлайн-first**: изменения сначала в `window.Cache` → мгновенный UI → фоновая запись в Firestore.
- **Firestore только через `getUserCol(tableName)`** из `core.js`. Прямые пути к коллекциям запрещены.
- **Финансовые параметры** (лимиты, пороги, правила категоризации) — только в `default-rules.js`, не в обработчиках.
- **UI на русском**, переменные/комментарии/функции — на английском.
- **Без emoji** в служебном UI; иконки — только Lucide (`iconsSVG.js`).

## Дизайн-система (Obsidian Minimalist / Anti-Slop)

- **Палитра:**
  - Фон экрана: глубокий OLED черный `#000000` (`--bg`).
  - Поверхности карточек: графитовый уголь `#0E1016` (`--surface`), вложенные `#151821` (`--surface-2`).
  - Границы: полупрозрачная hairline-нить `rgba(255, 255, 255, 0.07)` (`--line`), радиус карточек `14px`.
  - Текст: основной белый `#FFFFFF`, вторичный нейтральный slate `#8E96A4` / `#5F6775`.
  - Статусы: доходы/рост `#10B981` (emerald), расходы `#F43F5E` (rose), предупреждения `#F59E0B` (amber).
- **Кнопки (Стандарт Variant A):**
  - **Primary (Принятие / Создать / Сохранить):** чистый белый монохром `bg-white text-zinc-950 font-semibold shadow-sm hover:bg-zinc-100 active:scale-[0.98]`.
  - **Secondary (Отмена / Закрыть / Назад):** полупрозрачный графит `bg-white/[0.05] hover:bg-white/[0.09] text-zinc-300 border border-white/[0.08] active:scale-[0.98]`.
  - **Destructive (Опасные / Удалить):** полупрозрачный рубин `bg-rose-500/10 hover:bg-rose-500/20 text-rose-400 border border-rose-500/20 active:scale-[0.98]`.
- **Запрет на визуальный шум (Anti-Slop):**
  - Запрещены цветные pill-бейджи для нейтральных дат («Завтра», «Через 3 дн.»). Даты пишутся чистым вторичным текстом под суммой, без рамок и заливок.
  - Запрещены дублирующие подписи («Регулярный», «Счетов в месяц», формулы распределения капитала).
  - Хедер: аватар и служебные иконки должны быть чистыми и легкими, без массивных серых рамок-коробок.
  - Все финансовые суммы и даты — строго в `tabular-nums` (моноширинное выравнивание).

## Ключевые модули

- `core.js` — Firebase, `window.Cache`, утилиты, `getUserCol`
- `budget.js` — расчет суточного лимита, свободный остаток дня, главный дашборд бюджета
- `transactions.js` — реестр операций, фильтрация по периодам/категориям, поиск, группировка по датам, мультивыбор
- `tx-categories.js` — управление категориями, модалки создания/редактирования, каталог векторных иконок
- `tx-modal.js` — форма создания/редактирования операций, сплит-чеки, разовые траты/spread, автокатегоризация
- `tx-analytics.js` — аналитика и визуализация Chart.js (круговая диаграмма долей трат, столбчатая помесячная динамика)
- `statement-parser.js` — универсальное ядро парсинга выписок РФ (PDF.js, табличный сеточный парсер, диспетчер, UI импорта); правила банков — в модулях `banks/` (`sber.js`, `tbank.js`, `alfa.js`, `vtb.js`, `ozon.js`, `gpb.js`, `yandex.js`)
- `apk-features.js` — нативная интеграция Android (веб-код сюда не класть)
- `deposits.js` — вклады и накопительные счета, расчет капитализации
- `broker.js` — брокерский портфель, акции, БПИФы, рубли, котировки Мосбиржи
- `goals.js` — финансовые цели, копилки, доли накоплений от капитала
- `calendar-bills.js` — регулярные счета, шаблон и напоминания о платежах
- `moex-service.js` — клиент открытого REST API Московской биржи (MOEX ISS)
- `gemini-service.js` — интеллектуальный ассистент Google Gemini (выписки, дедупликация)
- `backup-manager.js` — экспорт/импорт, инспектор дубликатов
- `ui-tools.js` — модалки, тосты, дропдауны, общие UI-примитивы

## Ловушки, не видимые из кода

- `Cache.transactions` — массив **месяцев** (`[{ id: '2026-10', items: [...] }]`), не плоский список операций.
- Если задан `Cache.family?.id` → путь `families/{familyId}/…`, иначе → `users/{userId}/…`.
- **Не заменяй `Cache` целиком** — только мутируй поля, иначе слетят подписки UI.
- При ошибке записи в Firestore — откат локального изменения + тост.

## Коммуникация

- Вопрос или идея → режим обсуждения: ответь текстом, **не меняй код**.
- Прямая команда реализовать → действуй. Если при интеграции нужен рефакторинг соседних модулей — кратко опиши изменения.

## Использование субагентов (Subagents Policy)

- **Когда вызывать:**
  - Глубокий ресерч, локализация багов и анализ объемных файлов/логов, чтобы не засорять основной контекст (Context Offloading).
  - Изолированное тестирование и верификация парсеров выписок (`statement-parser.js`, `banks/`) на сырых данных.
  - Аудит написанного кода перед завершением задачи (проверка на offline-first `window.Cache`, `getUserCol`, Anti-Slop).
- **Когда НЕ вызывать:**
  - Для тривиальных правок в 1–2 строки, запуска одиночных команд (`npm run lint`) или простых ответов на вопросы пользователя.
- **Правило промпта (Self-contained):**
  - При вызове изолированного `subagent` обязательно передавай: контекст проекта (Capital, Vanilla JS PWA, offline-first), целевые файлы, ограничения (например, read-only) и критерий готовности.
  - При `subagent_fork` формулируй лаконичный целевой фокус, не дублируя уже известный контекст.
- **Формат ответа от субагента:**
  - Строго структурированный: 1) Вердикт/Статус, 2) Ключевые факты со ссылками на `файл:строка`, 3) Краткий diff или готовый план действий. Без пространных рассуждений.
- **Модели и рассуждения (DSH):**
  - Рутинный поиск/первичный аудит: `gemini-3.8-flash` с `reasoningEffort: medium` (быстро и экономично).
  - Сложная математика, архитектурная диагностика и аудит финансов (бюджет, сложный процент, брокер): `reasoningEffort: high`.
